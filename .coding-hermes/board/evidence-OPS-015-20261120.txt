Why the first pass could not see it (worker iteration record, reproduced and
source-checked in section 2 of this file): a NONZERO first exit latches
Result=exit-code, and service_enter_dead() only adopts a new result while the
previous one is SERVICE_SUCCESS (systemd v259 src/core/service.c:2118-2119), so
SERVICE_FAILURE_START_LIMIT_HIT (written only by service_test_startable(),
service.c:5673-5690) is observable only when the last death was a clean exit.
The brake itself is equally observable for a crasher as the refusal:
journal "Start request repeated too quickly.", Restart counter capped at
StartLimitBurst, ActiveState=failed, is-failed rc=0.

Disposition: the AC's named observable Result=start-limit-hit IS producible and
is now recorded; the blocked annotation is superseded. Code landing remains
